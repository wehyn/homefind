# HomeFind Implementation Plan

> **For implementers:** Follow repository instructions and the execution method agreed with the user. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an installable, mobile-first family inventory for one home, with photo-based item records, hierarchical locations, and name search.

**Architecture:** A self-hosted Next.js App Router server handles UI, authentication, authorization, and item operations. Better Auth and app records use SQLite on the same persistent local disk; private photo files live outside the public directory and are served only after a household-membership check. One app instance is used for v1.

**Tech Stack:** Next.js, TypeScript, npm, Better Auth, `better-sqlite3`, SQLite, and a single Docker Compose service with a durable data volume.

**Spec:** `docs/specs/2026-10-15-homefind-design.md`

**Implementation status (2026-10-16):** The initial app and Docker packaging are in the repo, and the Node 24 production build passes. The unchecked manual, device, backup/restore, and deployment checks remain open.

## Global Constraints

- Keep one household in v1. All members can view, add, edit, move, and delete items; only the owner can manage invitations.
- Use the selected Search-first screen: name search first, recent item rows with photo and full location path, one prominent add action.
- An item requires a name, one photo, and one saved location. Notes are optional.
- Locations are hierarchical. Search matches partial item names without case sensitivity.
- The app is online-first and remotely reachable only over HTTPS.
- Do not configure email delivery or a self-service password-reset flow in v1; a forgotten password cannot be reset through the app.
- Every server read or write checks the signed-in user and household membership. A user account alone never grants access to household data.
- Do not cache private item pages, API responses, or photo responses in a service worker or shared cache.
- Keep the SQLite database and photo files on the same persistent local volume. Never expose the upload directory as static public files or use a network filesystem for SQLite.
- Store only server-generated photo paths in SQLite. Reject invalid or oversized uploads and remove an uploaded file if its item save fails.
- Do not add offline sync, OCR, barcode scanning, multiple homes, or categories.

## Review Focus

- Unauthenticated and unrelated signed-in users must be denied on item pages, mutations, and direct photo requests.
- Invitation links must be unpredictable, expire after seven days, and stop working after one successful use.
- A caught database failure after photo upload must leave no incomplete item or orphaned photo. A process crash between file and database writes may leave an inaccessible orphan, as documented in the architecture.
- Restarting or updating the container must retain the database and photos; a restore must recover both.
- The phone photo picker may return a format the server cannot decode; the user must receive a clear retryable error, and the chosen iOS/Android formats must be verified on devices.

## File Map

Create the Next.js App Router project in the repository root. Keep server concerns under `src/lib/`, user-facing screens under `src/app/`, and deployment files at the root.

- `src/lib/db.ts` — one SQLite connection and app-owned schema setup.
- `src/lib/auth.ts` and `src/app/api/auth/[...all]/route.ts` — Better Auth configuration and Next.js handler.
- `src/lib/access.ts` — signed-in member and owner checks used by every protected operation.
- `src/lib/inventory.ts` — item search, item updates, location tree, and full location paths.
- `src/lib/invites.ts` — one-time invite creation and acceptance.
- `src/lib/uploads.ts` — image validation, private file writes, and cleanup on failed saves.
- `src/app/actions/items.ts`, `src/app/actions/locations.ts`, `src/app/actions/invites.ts`, and `src/app/actions/setup.ts` — validated server-side actions for the corresponding user flows.
- `src/app/page.tsx` — Search-first home screen.
- `src/app/settings/invitations/page.tsx` — owner-only invitation creation and link sharing, linked from Search for owners.
- `src/app/sign-in/page.tsx` — email/password sign-in.
- `src/app/items/new/page.tsx` — add-item form with camera/photo picker and location selection.
- `src/app/items/[id]/page.tsx` — item photo, name, full location, and edit/move actions.
- `src/app/api/items/route.ts` — authenticated multipart item creation.
- `src/app/api/items/[id]/photo/route.ts` — authenticated private photo response.
- `src/app/join/[token]/page.tsx` and `src/app/setup/page.tsx` — invitation acceptance and one-time initial owner setup.
- `src/app/manifest.ts`, `src/app/layout.tsx`, `src/app/globals.css`, and `public/icons/` — PWA metadata, app shell, responsive styles, and install icons sourced from a standard icon set.
- `Dockerfile`, `compose.yaml`, `.env.example`, and `README.md` — self-hosted runtime, durable data volume, setup, HTTPS, backup, and restore instructions.

## Task 2: Add SQLite persistence and inventory queries

**Files:** `src/lib/db.ts`, `src/lib/inventory.ts`, `src/lib/schema.sql`.

**Interfaces:**

- `type Actor = { userId: string; homeId: string; role: "owner" | "member" }`.
- `type ItemSummary = { id: string; name: string; photoUrl: string; locationPath: string; addedBy: string; updatedAt: string }`.
- `type LocationNode = { id: string; name: string; parentId: string | null; children: LocationNode[] }`.
- `type UpdateItemInput = { name: string; locationId: string; notes: string | null }`.
- `searchItems(actor: Actor, query: string): Promise<ItemSummary[]>`.
- `getLocationTree(actor: Actor): Promise<LocationNode[]>`.
- `updateItem(actor: Actor, itemId: string, input: UpdateItemInput): Promise<ItemSummary>`.

- [x] Open SQLite from `HOMEFIND_DATA_DIR`, enable foreign keys, and initialize the Better Auth-compatible and app-owned tables at startup.
- [x] Define household, membership, location, item, and invitation records. Add household-scoped foreign keys and indexes for item-name and location lookups.
- [x] Implement partial, case-insensitive item-name search with full location paths; show the most recently added items first.
- [x] Implement household-scoped location listing and item updates/moves; reject item or location IDs outside the member's household.

## Resolved decision

Defer self-service password recovery in v1. Do not configure SMTP or provide an in-app reset flow; a forgotten password cannot be reset through the app. SMTP-backed recovery can be added later.
